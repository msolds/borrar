LECCIÓN 1 · 25 MIN

Prepara la aplicación

Antes de empaquetar, asegúrate de que la aplicación no depende de configuraciones de desarrollo ni filtra información.

FUNDAMENTOS

i El escenario

El equipo está listo para publicar una aplicación Flask. En el entorno local todo funciona, pero el modo de depuración sigue activado y algunos valores de configuración están escritos directamente en el código. Esos atajos pueden revelar detalles internos o acabar exponiendo credenciales.

Tres decisiones antes del despliegue

1

Configuración fuera del código

Lee los valores del entorno. Usa datos ficticios en el laboratorio; los secretos reales deben gestionarse fuera del repositorio y rotarse si se exponen.

2

Desarrollo y producción son distintos

Desactiva el modo debug en producción. El servidor de desarrollo de Flask es una herramienta local, no un servidor de producción.

3

Registros sin datos sensibles

Registra eventos útiles para diagnosticar, pero no contraseñas, tokens, cookies ni datos personales innecesarios.

!

Regla práctica: si una credencial llegó al repositorio, borrarla del último commit no garantiza que haya desaparecido del historial. Revócala o rótala.

Comprueba lo aprendido

Encuentras una clave de prueba en el historial público del repositorio. ¿Qué haces primero?

RECUERDA

Una variable de entorno evita guardar el secreto en el código, pero no es una caja fuerte por sí sola. Limita quién puede leerla.

LECCIÓN 2 · 45 MIN

Endurece el contenedor

Un contenedor no es seguro por el mero hecho de estar aislado. Reduce su superficie de ataque y limita su impacto.

DOCKER
REVISIÓN DE DOCKERFILE 4 señales de riesgo
1FROM python:latest!
2WORKDIR /app
3COPY requirements.txt .
4RUN pip install -r requirements.txt
5COPY . .!
6EXPOSE 5000
7CMD ["flask", "run", "--host=0.0.0.0", "--debug"]!

▤

Fija la base

Evita etiquetas mutables como latest. Elige una versión mantenida y define cómo actualizarla y reconstruirla con regularidad.

♙

Reduce privilegios

Ejecuta el proceso con un usuario sin privilegios. Si la aplicación se compromete, esto limita lo que puede hacer dentro del contenedor.

◫

Incluye lo necesario

Usa .dockerignore, instala dependencias declaradas y minimiza archivos y herramientas incluidos en la imagen.

⌁

Sirve correctamente

Usa un servidor WSGI adecuado para producción. Añade una comprobación de salud y evita activar debug.

↗

Capas y caché: copia e instala primero el archivo de dependencias y copia después el código. Así Docker puede reutilizar la capa de instalación cuando el código cambia.

Comprueba lo aprendido

¿Qué aporta ejecutar la aplicación como usuario no root?

NO CONFUNDAS

EXPOSE documenta un puerto; no publica ni protege por sí mismo el servicio.

LECCIÓN 3 · 35 MIN

Despliega y verifica

Un despliegue seguro también requiere controlar quién puede acceder, comprobar que funciona y saber cómo volver atrás.

OPERACIÓN
01⌕

Valida antes

Ejecuta pruebas y análisis de dependencias. Revisa cambios, permisos del pipeline y que el artefacto construido sea el que vas a desplegar.

  • Pruebas pasan
  • Dependencias revisadas
  • Permisos mínimos
02⇧

Publica con control

Expón únicamente los puertos necesarios. Usa TLS en servicios publicados y limita el acceso administrativo.

  • Puertos justificados
  • Acceso restringido
  • Configuración de producción
03◉

Verifica y observa

Confirma la salud del servicio y monitoriza disponibilidad y errores. Evita que los registros incluyan secretos.

  • Health check responde
  • Alertas útiles
  • Logs sin datos sensibles
04↶

Prepara la vuelta atrás

Conserva una versión anterior identificable. Practica la reversión y verifica que las copias de seguridad se pueden restaurar.

  • Versión identificable
  • Reversión ensayada
  • Restauración comprobada

⌘
EMPIEZA AQUÍ

Abre el laboratorio

Cuando el proyecto esté en tu cuenta o en la organización del centro, pulsa el botón para crear un Codespace. Necesitarás una cuenta de GitHub con acceso a Codespaces.

Ir a GitHub Codespaces ↗

Busca el repositorio del curso y elige Code → Codespaces → Create codespace. Si ya tienes el repositorio clonado, ábrelo desde VS Code.

⌁
DENTRO DEL CODESPACE

Arranca la aplicación

En la terminal integrada, desde la raíz del repositorio:

cd laboratorio
docker build -t flask-lab .
docker run --rm -p 127.0.0.1:5000:5000 flask-lab

La configuración inicial es deliberadamente mejorable. Ejecútala solo en el Codespace privado. Detén el proceso con Ctrl + C.

!
USO RESPONSABLE

Solo en el entorno del curso

  • El proyecto es educativo y no contiene credenciales reales.
  • Mantén el puerto reenviado con visibilidad privada.
  • No despliegues la configuración inicial ni la dejes expuesta.
  • Al terminar, detén y elimina el Codespace si ya no lo necesitas.

No pruebes cambios de seguridad en sistemas ajenos ni en servicios públicos.
